# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

Sprachgesteuerter Entwicklungs-Assistent (multi-phase build, all 4 planned phases now implemented): user speaks into the mic, Gemini Live API responds with voice, a Flet desktop window shows connection status and a running transcript, plays two alternating personas (Duo-Mode), and a silent background critic can inject logic-error hints into the conversation. All in-code comments, docstrings, UI strings, and README are in German — match that when editing.

The full 4-phase roadmap and the 4 key design decisions behind it (why one AI plays both personas instead of switching connections, why speech rate control was dropped, etc.) live in `README.md` — read it before proposing architecture changes.

## Commands

Setup (Windows):
```
python -m venv .venv
.venv\Scripts\activate
pip install -r requirements.txt
```

Run:
```
python main.py
```

Tests:
```
pytest
```
Run a single test: `pytest tests/test_duo_mode.py::test_next_role_toggles`. There is no lint or build tooling configured. The `tests/` suite (`test_config.py`, `test_sessions.py`, `test_duo_mode.py`, `test_background_critic.py`) covers the pure-logic modules only — no mic/speaker/Gemini network involved; `BackgroundCritic.check()` is tested against a fake `client.aio.models.generate_content` (see the `_FakeClient` classes in `test_background_critic.py`), not the real API. `main.py` (the Flet UI + the real audio/Gemini wiring) has no automated tests — verify UI/audio changes by actually running `python main.py` (see the flet-version gotcha below before assuming a fresh window opens cleanly), or at minimum `python -c "import ast; ast.parse(open('main.py', encoding='utf-8').read())"` plus importing the non-GUI modules directly to catch syntax/import errors — `main.py` itself can't be imported without triggering `ft.run(main)` at module scope. When testing `main.py` manually, temporarily edit `config.json`'s `duo_mode`/`critic_enabled` to exercise those code paths, then restore it — `config.json` holds a real API key, don't leave it in a broken/half-edited state.

Config: copy `config.example.json` to `config.json` and set `api_key` (Gemini API key from Google AI Studio). `config.json` holds a real secret — never print its contents or commit it.

**flet version gotcha:** `requirements.txt` pins `flet>=0.24.0` (unbounded), but what actually gets installed is the current release, which as of this writing is `0.86.x` — a significantly newer API generation than 0.24, not just a patch bump. Notably: `page.window_width`/`page.window_height` don't exist anymore (use `page.window.width`/`page.window.height`); dialogs use a stack-based `page.show_dialog(dialog)` / `page.pop_dialog()` API instead of setting `dialog.open = True/False` + `page.update()`. Always check `dir(ft.Page)` / `inspect.signature(...)` against what's actually in `.venv` before assuming a Flet API from memory or older docs still applies — the two generations differ enough that plausible-looking old-style code fails silently or with `AttributeError` at runtime, not at parse time.

## Architecture

Nine modules, wired together in `main.py`:

- **`config.py`** — `AppConfig` dataclass loaded from `config.json` (or `GEMINI_API_KEY` env var as fallback for the key). Raises `SystemExit` with a German error message if no valid key is found. Fields include `input_device`/`output_device`, `duo_mode` (`"off"`/`"auto"`/`"manual"`), `critic_enabled`, `critic_model`, `critic_check_every`. `AppConfig.save_settings(config_path="config.json", **fields)` is a static helper that merges arbitrary keys into `config.json` without touching the rest — `save_voice(voice, ...)` is a thin wrapper around it, kept for readability at call sites. Voice and duo_mode only take effect on the next connect (both are baked into `LiveConnectConfig`/`system_instruction` at connect time), so saving writes to disk but doesn't hot-swap the live session.
- **`sessions.py`** — Conversation history persistence. `save_session(transcript: list[dict])` writes the in-memory transcript log (`[{"who": ..., "text": ...}, ...]`) to a timestamped JSON file under `sessions/`. `list_sessions()` / `load_session(path)` read them back. Loading a session is read-only display — it does not resume any live Gemini conversation context, it's just replaying old text.
- **`duo_mode.py`** (Phase 3) — Pure logic, no I/O. `build_system_instruction(base, mode, start_role=...)` appends Duo-Mode rules to the base `system_instruction` depending on mode: `"auto"` tells the model to switch roles after every response on its own; `"manual"` tells it to hold a role until told otherwise. `next_role(current)` toggles between `ROLE_VISIONAER`/`ROLE_PRAGMATIKER`. `build_switch_message(role)` builds the invisible text nudge sent via `send_text()` for manual switches. There's no way to detect which role the model is *actually* in for `"auto"` mode — only `main.py`'s locally-tracked `current_role` state (used for manual mode's UI label) is authoritative, and only for manual mode.
- **`background_critic.py`** (Phase 4) — The closed-loop critic. `build_critic_prompt(transcript_log, window=12, code_snippet=None, prior_hint=None)` and `parse_critic_response(text)` are pure functions (prompt in, `"OK"` or `"HINWEIS: ..."` parsed out). The optional `code_snippet` (typically the live clipboard content, threaded in from `main.py`) gets its own labeled section in the prompt ("Code-Ausschnitt aus der Zwischenablage:") ahead of the transcript, and `CRITIC_PROMPT_HEADER` explicitly tells the model to cross-check claims like "das ist jetzt gefixt" against it; the optional `prior_hint` gets its own section too ("Offener Punkt aus letzter Sitzung:") with an instruction to check whether it's now resolved — both sections are omitted entirely (no instruction change needed) when their argument is `None`/blank, so behavior for the plain-brainstorm case is unchanged. `extract_last_hint(records)` is the cross-session half: scans saved session records (from `sessions.load_session()`) backwards for the last entry with `who == "Kritiker"` and returns its text, or `None`. That convention — `main.py`'s `run_critic_check()` appending `{"who": "Kritiker", "text": hint}` directly to `transcript_log` (not via `add_transcript_line()`, to avoid re-triggering `register_turn()`/the styled speech-bubble UI) — is what makes hints round-trip through `save_session()`/`load_session()` for free, no schema change needed. `wrap_hint(hint)` builds the invisible text nudge sent via `send_text()`. `BackgroundCritic` ties it together: `register_turn(who)` counts user turns and returns `True` every `check_every` turns (call site decides what to do with that); `check(transcript_log, code_snippet=None, prior_hint=None)` makes a **separate, non-live** `client.aio.models.generate_content()` call (not the Live API — a plain text completion) and returns the parsed hint or `None`. Network/API errors inside `check()` are caught and swallowed (returns `None`) — a broken critic must never crash the live voice session, only silently skip that round.
- **`audio_engine.py`** — `AudioEngine` owns the `sounddevice` input/output streams, running in their own audio threads. Mic input is captured at 16 kHz (`INPUT_RATE`, what Gemini expects), playback is at 24 kHz (`OUTPUT_RATE`, what Gemini returns) — these rates are asymmetric by design, don't unify them. Mic callback pushes int16 PCM chunks into `mic_to_gemini` (an `asyncio.Queue`, bridged from the audio thread via `loop.call_soon_threadsafe`); when full, oldest chunk is dropped to stay live. Playback works the opposite direction: `speaker_feeder()` (an asyncio task) drains `gemini_to_speaker` into a `deque` of chunks that the output stream's callback pulls from under a `threading.Lock`, since that callback runs on the audio thread, not the event loop. `clear_playback()` is called on user-interrupt to stop the AI from "talking over itself". `list_audio_devices()` is a module-level function (not a method) used for the startup diagnostic printout.
- **`code_context.py`** (Code-Kontext-Grounding) — Pure logic, no I/O in the formatting function. `build_context_message(clipboard_text, max_chars=4000)` turns raw clipboard text into the invisible German system-hint text sent via `send_text()`; returns `None` for empty/whitespace-only input, truncates and appends a "(gekürzt)" note past `max_chars`. `read_clipboard(paste_fn=None)` is the one I/O wrapper — defaults to `pyperclip.paste`, but accepts an injectable `paste_fn` so it stays unit-testable without a real clipboard; like `BackgroundCritic.check()`, any exception (no clipboard access, `pyperclip` missing a backend, etc.) is swallowed and returns `None` rather than crashing the live session. There is no git-diff variant — the project itself isn't a git repo, so that path was dropped rather than built untested.
- **`session_memory.py`** (Cross-Session-Gedächtnis) — Pure prompt-building (`build_summary_prompt`, `build_resume_message`) plus one I/O function, `summarize_session(client, model, records)`, that makes a **separate, non-live** `generate_content()` call — exact same pattern as `BackgroundCritic.check()`, including swallowing every exception and returning `None`. `records` come straight from `sessions.load_session()`; an empty list returns `None` without ever calling the model. `main.py` wires this at connect time only (not per-turn): `handle_status()` watches for the exact string `"Verbunden"` (not `"Verbunden (unterbrochen)"`, which also starts with "Verbunden" but isn't a fresh connect) and fires `send_resume_context()` exactly once per `session.run()`, via a `resume_sent` flag — it loads the most recent session from `list_sessions()[0]` (skipped if none exist), summarizes it, and — only if a non-empty summary came back — injects it via `session.send_text()`. Reuses `config.critic_model` as the summarizer's text model (and `text_client`, a single shared `genai.Client`) rather than adding a new config field — that field already means "cheap non-live text model for background calls" and exists in `AppConfig` regardless of `critic_enabled`.
- **`gemini_session.py`** — `GeminiLiveSession` opens one `google-genai` Live API connection (`client.aio.live.connect`) and runs `_send_loop` (mic queue → `session.send_realtime_input`) and `_receive_loop` (`session.receive()` → routes audio to `audio.gemini_to_speaker` and transcript text to the `on_transcript` callback) as concurrent tasks alongside a stop-event waiter, via `asyncio.wait(..., FIRST_COMPLETED)`. `_is_normal_close()` distinguishes a clean server-side close (code 1000 / `ConnectionClosedOK`) from a real error — only real errors propagate up. `content.interrupted` from the server triggers `audio.clear_playback()`. `send_text()` injects invisible text turns into the live session — used by both `duo_mode`'s manual role switch and `background_critic`'s hints. Note: the Live API's `SpeechConfig` only supports `voiceConfig` + `languageCode`, no speech-rate/speed parameter — don't add a "Sprechtempo" setting that assumes the API accepts one (confirmed by inspecting `google.genai.types.SpeechConfig`'s signature).
- **`main.py`** — Flet app entry point (`ft.run(main)`). Builds the UI (status dot, transcript `ListView`, mute button, settings gear icon with voice + duo_mode dropdowns, session save/open buttons, "Rolle wechseln" button shown only when `duo_mode == "manual"`, and a "Code-Kontext senden" button always visible), constructs `AudioEngine` and `GeminiLiveSession` wired via callbacks (`on_status`, `on_transcript`), starts `audio.start()` then runs `session.run()` as the main coroutine, with `speaker_feeder()` as a background task. `do_send_context()` reads the clipboard via `code_context.read_clipboard()`, builds the hint via `code_context.build_context_message()`, and — only if `session.session is not None` (i.e. actually connected) — fires `session.send_text()` as a background task; a no-op with a status message otherwise, same pattern as `do_switch_role()`. Rewrites `config.system_instruction` via `duo_mode.build_system_instruction()` right after loading config, before constructing `GeminiLiveSession` — that's the single integration point, `gemini_session.py` itself is untouched by Duo-Mode. Maintains an in-memory `transcript_log` list (appended to in `add_transcript_line`, which also backs the "Sitzung speichern" button); if a `BackgroundCritic` is configured, `add_transcript_line` calls `critic.register_turn()` on every line and fires `run_critic_check()` as a background `asyncio.create_task` when it returns `True`; `run_critic_check()` re-reads the clipboard via `code_context.read_clipboard()` on every check and passes it into `critic.check(transcript_log, code_snippet=...)`, so the critic's checks stay current with whatever's on the clipboard at check time, not just what was there when Code-Kontext-Grounding was last manually triggered. `page.on_disconnect` triggers graceful shutdown (`shutdown()`: auto-saves `transcript_log` via `save_session()` if non-empty, then `session.stop()` + `audio.stop()`) — this auto-save is what makes Cross-Session-Gedächtnis reliably have something to resume from, since users don't always remember to click "Sitzung speichern". `on_status` is `handle_status()`, not a plain lambda, precisely so it can also detect the first `"Verbunden"` and kick off `send_resume_context()` (Cross-Session-Gedächtnis) exactly once per connection. `add_system_note(text)` appends a small, grey, locally-only line to `transcript_view` — never to `transcript_log`, so it's invisible to the KI/critic/session-memory, purely a UI signal — called right after both silent `send_text()` injections (the critic's hint in `run_critic_check()`, the resume summary in `send_resume_context()`) so the user has visible proof those background features actually fired, instead of the injections being entirely invisible. A `prior_critic_hint: str | None` closure variable, set once by `send_resume_context()` via `background_critic.extract_last_hint()` on the previous session's records, is read (not reassigned, so no `nonlocal` needed there) by every later `run_critic_check()` this connection and passed as `critic.check(..., prior_hint=...)` — best-effort only: if a critic check somehow fires before `send_resume_context()` finishes (both are independent background tasks), it just runs without the prior hint, same as if there were no previous session.

Data flow: mic thread → `mic_to_gemini` queue → Gemini Live API → `gemini_to_speaker` queue → speaker thread, with transcript text and status pushed to the Flet UI via plain callbacks (no framework state management). The background critic is a side-channel: it reads `transcript_log`, makes its own separate API call, and writes back into the live session only via `send_text()` — it never touches the audio path directly.

## Roadmap context (from README)

All 4 planned phases are implemented. Duo-Mode (Phase 3) and the background critic (Phase 4) are both off by default in `config.example.json` (`duo_mode: "off"`, `critic_enabled: false`) — flip them on in `config.json` to use them.
